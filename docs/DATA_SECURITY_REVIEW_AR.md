# مراجعة مسار البيانات وسياسة التعامل معها

## 1) مسار البيانات في النسخة الحالية

هذا الوصف مطابق لبنية الكود الحالية بعد إضافة JWT/RLS، وليس تعهدًا أمنيًا من مزودي الخدمة:

1. المستخدم يختار PDF في Streamlit.
2. Streamlit server يرسل الملف إلى FastAPI `/upload` عبر HTTPS عند استخدام الروابط المنشورة.
3. Backend يتحقق من هوية المستخدم وصلاحية `documents:write` والـ Tenant، ثم يتحقق من امتداد PDF وحجمه وتوقيعه.
4. Backend يكتب **الـ PDF الأصلي** إلى مجلد محلي على حاوية Backend تحت `DATA_DIR/<tenant_id>/`.
5. PyMuPDF يستخرج النص، ثم يقسمه إلى chunks ويضيف metadata مثل tenant واسم الملف والصفحة ونطاق الوصول.
6. نصوص chunks تُرسل إلى Gemini Embedding API (`gemini-embedding-001`) لإنشاء embeddings.
7. قاعدة Supabase Postgres/pgvector تخزن النص الكامل لكل chunk والـ metadata والـ embedding. حماية الصفوف تتم عبر RLS وسياسات tenant/role/user.
8. عند السؤال، نص السؤال يُرسل إلى Gemini Embedding API للبحث.
9. النص المسترجع المصرح به مع السؤال يُرسل إلى Gemini Generation API (`gemini-3.6-flash`) لتوليد الإجابة.
10. Streamlit يعرض الإجابة والمصدر والصفحة ومقتطف الدليل للمستخدم.

### ما الذي يغادر بيئة الشركة؟

- ملف PDF الأصلي: يمر عبر Streamlit إلى Backend ويُخزن على نظام ملفات الحاوية.
- محتوى المستند المستخرج: يرسل إلى Google Gemini لإنشاء embeddings.
- السؤال ومقتطفات الأدلة المسترجعة: تُرسل إلى Google Gemini لتوليد الإجابة.
- chunks والنصوص والـ embeddings والـ metadata: تخزن في Supabase Postgres.

## 2) ما الذي لم يصبح جاهزًا بعد؟

- ملفات PDF الأصلية ما زالت تُحفظ على القرص المحلي لحاوية Backend، وليست في Supabase Storage private bucket أو مخزن S3 خاص بالشركة.
- ملفات الحاوية في SnapDeploy مؤقتة؛ وثائق SnapDeploy تنص على أن الملفات المحلية تُفقد عند إعادة تشغيل الحاوية، وتوصي باستخدام Object Storage مثل S3 أو R2 أو Spaces. لذلك أي PDF مرفوع حاليًا إلى `DATA_DIR` قد يختفي عند إعادة التشغيل، ولا يوجد في المشروع الحالي تكامل مع مخزن ملفات دائم.
- endpoint `DELETE /documents/{tenant_id}` يمسح vector rows فقط، ويُبقي ملفات PDF الأصلية كما توضح رسالة API. لا توجد بعد سياسة حذف موحدة للنسخ الأصلية والـ chunks والنسخ الاحتياطية.
- لا توجد شهادة/مراجعة مستقلة لإعدادات مشروع Supabase الخاص بك. كما أن شروط Streamlit Community Cloud تنص على عدم استخدام الخدمة لمعالجة المعلومات المالية أو المعلومات الشخصية الحساسة؛ لذلك لا تستخدم Streamlit Community Cloud مع ملفات مالية حقيقية أو سرية للشركة. استخدم واجهة مستضافة داخل بنية الشركة أو منصة مؤسسية وافقت عليها الشركة.
- لا توجد بعد منظومة كاملة لتدقيق كل دخول/تنزيل/حذف، أو نسخ احتياطي واختبار استعادة، أو إدارة مفاتيح مركزية.

**النتيجة:** لا ترفع مستندات الشركة السرية إلى النسخة الحالية لمجرد أن JWT وRLS أُضيفا. يلزم أولًا نقل PDF إلى تخزين خاص دائم، وتحديد الحذف والاحتفاظ، ومراجعة عقود ومواقع تخزين مزودي الخدمة، ثم اختبار استعادة النسخ الاحتياطية.

## 3) عوائق المنصات الحالية

- **SnapDeploy:** الحاويات عابرة (ephemeral). ملفات PDF الأصلية المحفوظة في `DATA_DIR` لن تكون تخزينًا دائمًا، وقد تضيع عند restart. يجب نقلها إلى private object storage قبل أي مستندات مهمة.
- **Streamlit Community Cloud:** لا تستخدمه لمعالجة معلومات مالية أو بيانات شركة حقيقية؛ شروط الخدمة تمنع ذلك. استخدم استضافة واجهة خاصة/مؤسسية بعد مراجعة شروطها.
- **Gemini API:** لا تستخدم الحصة المجانية للمستندات السرية. شروط Google تقول إن الخدمات غير المدفوعة قد تستخدم prompts والملفات والردود لتحسين المنتجات، وقد يراجع البشر هذه البيانات.

## 4) سياسة مقترحة قبل Pilot ببيانات الشركة

استخدم بيانات مصطنعة أو منقّحة حتى يوقع العميل موافقته على مسار البيانات. قبل إدخال بيانات حقيقية، وثّق هذه القرارات مع الشركة:

| البند | القرار الذي يجب توثيقه |
|---|---|
| تصنيف المستندات | عام / داخلي / سري / شديد السرية |
| مكان PDF الأصلي | Private Supabase Storage bucket في منطقة متفق عليها أو S3/Object Storage داخل بيئة الشركة |
| مكان قاعدة البيانات | مشروع Supabase مملوك للشركة وفي Region توافق عليه الشركة، أو PostgreSQL داخل بيئتها |
| الوصول | حسابات حقيقية، MFA عند الحاجة، tenant/role/user permissions من الخادم، مراجعة دورية للحسابات |
| الاحتفاظ | عدد أيام الاحتفاظ بالـ PDFs والـ chunks والـ embeddings والـ logs والنسخ الاحتياطية |
| الحذف | آلية موثقة لحذف PDF الأصلي والـ chunks والـ embeddings والنسخ المخزنة المؤقتة، وتحديد مهلة التنفيذ |
| Gemini | خطة مدفوعة مرتبطة بـ Cloud Billing، مراجعة DPA وشروط المعالجة، وتحديد هل مسموح إرسال مقتطفات مستندات إلى Google |
| السجلات | عدم تسجيل كلمات المرور أو Tokens أو مفاتيح API أو نصوص المستندات في logs |
| النسخ الاحتياطي | تكرار النسخ واختبار الاسترجاع وتحديد RPO/RTO والمسؤول عن الاستعادة |
| الاستجابة للحوادث | جهة اتصال، طريقة إيقاف الحسابات وتدوير المفاتيح وإبلاغ الشركة |

## 5) ملاحظة مهمة عن Gemini API

حسب شروط Gemini API السارية من 23 مارس 2026:

- في الخدمات غير المدفوعة، قد تستخدم Google prompts والملفات والردود لتحسين الخدمات، وقد يراجع أشخاص من Google مدخلات ومخرجات API؛ لذلك تنص الشروط على عدم إرسال معلومات حساسة أو سرية أو شخصية إلى هذه الخدمات.
- في الخدمات المدفوعة المرتبطة بمشروع Cloud له حساب Billing نشط، تقول الشروط إن prompts والردود لا تُستخدم لتحسين المنتجات، وتخضع لـ Data Processing Addendum. لكنها قد تُسجّل لفترة محدودة لأغراض السلامة والأمن والالتزامات القانونية، وقد تُخزّن مؤقتًا في أي بلد تعمل فيه Google أو وكلاؤها.
- لا يكفي أن يكون عندك API key؛ راجع أن مشروع Gemini API فعليًا على Paid Services، وراجع DPA وسياسة الشركة وموافقتها قبل الإرسال.

## 6) أسرار الاتصال

| السر | مكانه المسموح |
|---|---|
| `SUPABASE_DB_URL` وكلمة مرور قاعدة البيانات | Backend secret store فقط |
| `GEMINI_API_KEY` | Backend secret store فقط |
| Supabase service role / secret key | لا يُضاف إلى Streamlit أو GitHub. الأفضل عدم استخدامه في هذا المسار |
| Supabase publishable/anon key | يمكن وضعه في Streamlit Secrets؛ هو مفتاح عميل عام ويجب أن تكون RLS صحيحة |
| Supabase user access token | يحفظ مؤقتًا في جلسة Streamlit ويرسل إلى Backend عبر Authorization Bearer |

## 7) شروط السماح بتجربة حقيقية

لا تعتبر النظام جاهزًا لاستقبال ملفات سرية إلا بعد:

- تفعيل `AUTH_MODE=supabase_jwt` في Backend وStreamlit معًا.
- نجاح جميع اختبارات JWT وtenant وrole وRLS، بما فيها الاختبار من Data API مباشرة.
- نقل PDF الأصلي من قرص الحاوية إلى تخزين خاص دائم مع صلاحيات وحذف واضحين.
- اعتماد خطة Gemini المدفوعة وDPA أو استبدالها بنموذج استدلال/Embedding داخل بيئة الشركة.
- موافقة مكتوبة من الشركة على منطقة استضافة Supabase وSnapDeploy/بديل الاستضافة وStreamlit Cloud أو استضافة الواجهة داخل بيئة خاصة.
- إعداد النسخ الاحتياطية والحذف والسجلات والاستجابة للحوادث.

هذا المستند قائمة هندسية لتجهيز Pilot، وليس شهادة امتثال قانوني أو ضمانًا لأمان مزودي الخدمة.
